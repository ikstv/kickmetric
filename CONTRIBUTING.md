# Contributing to KickMetric

KickMetric is in planning. Documentation corrections, focused proposals, and questions about the project direction are welcome.

## Before proposing a change

Read the [vision](docs/vision.md), [roadmap](docs/roadmap.md), and [decision register](docs/decisions.md). Search existing issues to avoid duplicate discussions.

Use a feature request to explain a problem, intended user value, alternatives, and open questions. Use a bug report for a documentation, link, branding, or repository problem. There is no application to install or run yet.

## Pull requests

- Keep each change focused and write repository-facing text in English.
- Explain the reason for the change and link any related issue.
- Distinguish proposed capabilities from approved decisions and completed work.
- Check relative links and image paths. Preview documentation and visual changes where possible.
- State exactly what you verified and any checks you could not perform.
- Exclude credentials, private information, local configuration, and data or assets without appropriate usage rights.

The project owner makes final product and architectural decisions. Discuss substantial changes before implementation. Substantial code contributions should wait until licensing and the implementation approach have been clarified.

License selection is pending the project owner's decision. Public visibility does not itself grant an open-source license.
