# Project vision

## Problem and intended value

A football forecast is difficult to assess when its inputs, uncertainty, and past performance are unclear. KickMetric aims to connect match probabilities with the information behind them, making forecasts understandable, measurable, and transparent about uncertainty.

The intended value is to help people compare teams, examine why a forecast was produced, and review how forecasts perform over time. The initial user audience and priority use cases still need definition with the project owner.

## Confirmed direction

- The project is named KickMetric and uses a public repository named kickmetric.
- The purpose is forecasting football match results and analyzing the information behind forecasts.
- A desktop application for PC comes first. Android is a future goal.
- Specific desktop operating systems and minimum requirements are not selected.
- The owner makes final product and architectural decisions; agents implement approved tasks and raise recommendations for discussion.

## Proposed initial scope

The following capabilities are candidates for discussion, not approved features:

- Pre-match home-win, draw, and away-win probabilities.
- Team-form and historical-performance comparisons.
- Explanations of the information used in a forecast.
- A record of forecasts and subsequent outcomes.
- Evaluation against simple baseline predictions.

Forecasts will express uncertainty rather than guarantees. No predictive performance has been established.

## Boundaries of the current task

The foundation consists of documentation, repository guidelines, contribution templates, and an initial visual identity. It does not include an application, trained model, dataset, or release.

Programming languages, UI framework, backend architecture, database, data providers, prediction models, initial leagues, licensing, monetization, and application localization remain undecided. English repository documentation does not decide the application's language support.

See the [decision register](decisions.md) for approval boundaries and the [roadmap](roadmap.md) for proposed next stages.
