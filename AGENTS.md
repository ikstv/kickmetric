# Agent guidelines

Read README.md, docs/vision.md, docs/roadmap.md, docs/decisions.md, and CONTRIBUTING.md before making changes.

- Keep repository content, commit messages, GitHub descriptions, and templates in English.
- Implement the approved task scope. Avoid unrelated changes and premature application scaffolding.
- The project owner makes final product and architectural decisions. Present major choices as recommendations for approval; earlier suggestions are not approvals.
- Keep changes focused and reviewable. Separate confirmed decisions, proposals, and unresolved questions in documentation.
- Never publish secrets, private information, or data without appropriate usage rights. Inspect staged files and any history that will become public.
- Never invent capabilities, forecasts, benchmark results, or test outcomes. Do not describe planned work as implemented.
- For future forecasting work, use only information available at prediction time and evaluate on later, unseen matches. Check temporal leakage and compare with simple baselines.
- Validate relevant links, assets, and behavior using tools appropriate to the change. Do not invent development commands before a stack exists.
- Report what changed, what was verified, and what remains unresolved. State any verification limits.

This repository is in planning. Do not select a license, technology stack, data provider, prediction model, or release target without the owner's approval.
